# 黑馬記念26-27 操作手冊

## 入口與場次

管理員由 `?admin=1` 登入，在系列賽選擇「黑馬記念26-27」。系列公開代碼為 `BH2627`。積分賽第一場至積分賽第四場使用 `BH2627S1` 至 `BH2627S4`，最終戰為 `BH2627F`。場次卡在後台建立實際賽事後才會出現在公開系列頁。清除場次會建立新的 run 並保留歷史版本。

獨立賽事建立表單可勾選「使用 26-27 積分賽規則」。四站與新制獨立賽採用 `qualifier-26-27`，最終戰採用 `final-26-27`。新建一般單場使用 `legacy-v1`；沒有規則版本的歷史場次仍依舊制讀取。

## 報名與核對

選手可以逐筆登錄或匯入 UTF-8 CSV。欄位依表頭辨識，可調換順序。電話欄應保存為文字以保留開頭的零。

```csv
本名,電話號碼,打師名
王小明,0900000000,小馬
```

本名與電話都相符時沿用選手編號。同本名、同電話或打師名變動引發衝突時，畫面列出報名內容與候選資料，管理員可確認沿用對象與打師名。只有部分相符時也可確認為不同選手。CSV 逐筆處理，遇到衝突會暫停並保留剩餘列。已成功加入的選手立即寫入該站，重新匯入前可先查名單。

私人選手檔位於 `privatePlayers/{playerId}`，本名及電話的查重索引位於 `privatePlayerIndex`。兩者僅管理員可讀寫；索引與選手檔由同一交易更新。管理端透過 Firestore Lite 讀取，個資不進入公開賽事的 IndexedDB 快取。每場名單、配對、完賽版本及系列排行使用穩定編號與當場打師名。往後改名不覆寫舊場次的公開打師名。

## 積分賽

- 正式名單上限 48 位。開賽時遇到奇數，系統加入「主辦」，其比賽照常投票、計算勝敗與對手勝率。
- 三輪、三票，兩敗淘汰。第三輪將成奇數時，復活排名最高且未棄賽的兩敗選手。最高並列時，後台須裁定人選。棄賽造成奇數且沒有可復活者時，輸入一位實際出賽的主辦方補位者。
- 配對成立後即保存先後攻。左側先攻，比分按相同方向登錄。棄賽保留已完成對戰，當輪尚未完成的對戰判對手獲得全票。
- 結算先排除主辦方選手，再依勝場、總票數、對手勝率、對手的對手勝率排名。每人依同戰績組內共同名次領取積分。系列按選手編號取四站中的最佳三站，相同站分依站次擇先標示「採計」，不影響總分。

## 最終戰

1. 四站全部完賽後，選擇兩位線上保送及一位現場海選。未參加積分賽的選手可在對應席位按「新增選手」，填寫本名、電話號碼、打師名，再按「儲存並填入席位」。已有選手檔者可直接從下拉選單選取。系統排除線上保送者，再取積分榜前 21 位，其中前六位為種子。海選須為另一人。
2. 影響 21 人名單、種子或首輪配對的同分，需要逐位裁定。確認開賽交易會重新核對四站版本，保存資格來源、24 人名單與種子。日後積分賽更正仍會更新系列榜，已開賽的最終戰使用原確認名單。
3. 首輪八個種子各記一勝五票，其餘 16 人頭尾相配。第二、三輪全員參賽，每輪 12 場。種子勝績計入本人勝率，不產生虛構對手。
4. 瑞士制前三輪完成後，必要時裁定並列順序，再產生八強籤表。上半區 1–8 與 4–5，下半區 2–7 與 3–6。五票多數晉級。四強敗者進入季軍戰，勝者進入冠軍戰。
5. 兩場獎牌戰都完成才可結算。更正已登錄比分須填原因；若晉級人選改變，確認畫面列出受影響場次。重新計分時保留其他對戰及比分。已完賽的最終戰若需要補登，系統建立更正版本並重新開放，再於補登完成後鎖定。可在同一 run 回復先前已鎖定的版本。

## 公開畫面與發布

`?event={場次代碼}` 顯示即時或完賽排行榜與瑞士制樹狀圖，最終戰另顯示淘汰籤表與獎牌結果。`?series=BH2627` 顯示公開場次、各站得分及採計站。手機排行榜採單列換行。

發布本版時先部署儲存庫的 Firestore 規則，再發布前端，讓管理端可存取選手文件與索引。網站測試使用本機模擬器，毋須在正式資料庫建立測試選手。
