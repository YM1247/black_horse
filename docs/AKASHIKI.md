# 赤式x黑馬記念合作賽

## 入口與識別

此賽為獨立單場賽事，不屬於黑馬 26–27 系列，也不計入四站積分。後台 `?admin=1` 首頁「系列賽與特殊賽」中，合作賽與黑馬系列賽並列；首次點選建立，之後點選開啟既有賽事。

英文識別與賽制版本使用 `Akashiki`。公開賽事代碼依既有系統慣例正規化為大寫 `AKASHIKI`，公開網址為 `?event=AKASHIKI`。賽事實際建立後才有可查詢的賽程。

## 瑞士制

- 確認 2–32 位正式選手後可開賽（未滿 32 位也可，奇數時由主辦補位），固定三輪，每輪三位評審、每場三票。未棄賽選手即使兩敗仍參與第三輪。
- 排名順序：總票數、勝場、對手勝率、對手的對手勝率，全部由高至低比較。勝率公式沿用黑馬 26–27。
- 首輪隨機配對。第二、三輪沿用黑馬的分組／向下浮動機制，但主分組改為總票數；同票組依勝場與兩級對手勝率排序，組內優先避免重複對手。奇數組將組內排名最後一人下移至下一票數組。
- 選手核對、逐筆報名、CSV 匯入、先後攻抽選與比分更正沿用黑馬 26–27。開始比賽後不能再增補一般報名。
- 棄賽前的成績保留；當輪未完成對戰判對手全票。若下一輪為奇數人，管理員須指定實際出賽的主辦方補位者。合作賽不使用兩敗復活。
- 主辦方補位不占十六強名額；棄賽者不入圍。若可入圍者不足 16 人，系統不產生不完整籤表。

## 十六強與獎牌戰

1. 三輪全部完成後，依瑞士制排名取前 16 位。僅跨越第 16 名的完全並列需要加賽，完成後在後台登錄加賽結果順序；完全在入圍範圍內的並列不需要種子順序。
2. 點選「隨機抽出十六強籤表」，16 人全員隨機分配籤位，無排名種子保護。抽籤與每場先後攻保存於同一場賽事文件，重新載入不會重抽。
3. 十六強、八強、四強、季軍戰皆為 BO1，每場三票多數晉級。四強敗者打季軍戰，勝者打冠軍戰。
4. 冠軍戰為 BO3、先贏兩局者勝。每局三位評審，分別登錄 `3:0`、`2:1`、`1:2`、`0:3`；總比分顯示局數，並另列每局票數。`2:0` 不開第三局，`1:1` 才開第三局。
5. 冠軍戰與季軍戰都完成後，才可「結算並鎖定結果」。公開頁顯示十六強籤表、逐局冠軍戰、冠亞季軍與瑞士制排名，不顯示系列積分。

前後台的十六強籤表由左至右以「十六強 → 八強 → 四強 → 冠軍戰」樹狀圖呈現，連線標示勝者晉級路徑。季軍戰置於冠軍戰下方，明示四強敗者來源。尚未決定的對戰保留來源標示，已完成對戰以暖色強調勝者。後台直接在同一棵樹上記分，冠軍戰仍逐局操作。合作賽後台讓樹狀圖占整個內容寬度，瑞士排名放在下方。

手機保留完整樹狀結構，由圖內水平滑動查看後續輪次，不讓整頁產生水平溢位。圖區可使用鍵盤聚焦捲動。第一輪對戰內容變高時，自動等比例增加各輪垂直間距，避免長打師名換行後重疊並維持連線對齊。

## 更正與歷史版本

- 更正已登錄比分須填寫原因；晉級人選改變時，只清除受影響的後續對戰，保留其他比分。
- 瑞士制更正會重算排名；已抽出的十六強名單、籤位與比分固定，不因瑞士制排名改變而重新配對。抽籤前跨入圍線並列須先完成加賽。
- BO3 更正逐局重算局數；若更早已達兩勝，捨棄不應進行的後續局。若原本 `2:0` 改成 `1:1`，重新開放第三局。
- 已鎖定結果透過既有不可變版本機制更正；需要補賽時建立更正版本並重新開放，補登後再次結算。Firestore 規則沿用既有 `bracket` 鎖定保護；每局位於該欄位內。

## 實作與驗證

- `tournamentState.js` 固定專屬規則、三票與不兩敗淘汰，並正規化保存淘汰籤表。
