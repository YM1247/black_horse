# Phase 1 實作說明

## 範圍

Phase 1 完善單場三輪瑞士制賽事，包含兩項資料與規則變更：

1. 選手不再保存或顯示代表學校，只以名稱識別。
2. 賽事建立階段可選擇三位或五位評審，每場比分總和必須等於評審人數。

## 資料模型

選手資料：

```js
{
  id: string,
  name: string,
  wins: number,
  votes: number,
  isWithdrawn: boolean
}
```

賽事資料新增 `judgeCount: 3 | 5`，並與 `phase`、`players`、`rounds`、`currentRoundNum` 一起寫入目前進度及每一筆歷史存檔。

對戰比分由 `judgeCount` 產生：

- 三位評審：`3:0`、`2:1`、`1:2`、`0:3`
- 五位評審：`5:0`、`4:1`、`3:2`、`2:3`、`1:4`、`0:5`

兩種賽制都是奇數票，不會產生平手。

## 舊資料遷移

載入目前進度或歷史存檔時會執行標準化：

- 移除選手與對戰快照內的 `school`。
- 保留 ID、名稱、勝場、得票、棄賽狀態與既有對戰。
- 舊存檔沒有 `judgeCount` 時，優先從第一場已完成對戰的票數總和推斷；無已完成對戰則預設五位評審。
- 新歷史存檔使用 `swiss_tourney_saves_v4`，首次載入時可讀取舊版 `v3`。

## 操作流程

1. 在報名畫面選擇評審人數。
2. 手動新增選手，或匯入 CSV 第一欄的選手名稱。
3. 至少兩人後開始抽籤；評審人數從此固定至本場賽事結束。
4. 為每場對戰選擇比分；全數完成後才可進入下一輪。
5. 三輪完成後顯示最終排名並自動建立完賽存檔。

## 驗證範圍

自動化測試驗證：

- 報名畫面與選手清單沒有學校欄位。
- 三位評審賽事只顯示總和為三的四種比分。
- 舊版選手資料可載入，且重新保存後不含 `school`。

另外以 production build 驗證 JSX、Tailwind 與打包流程。
