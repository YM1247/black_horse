# AKASHIKI 誤刪修復與清除功能

## 問題與修復

2026-11-17 直接讀取正式 Firestore 確認 `tournaments/AKASHIKI` 回傳 404，但 `tournamentSummaries/AKASHIKI` 仍記錄完賽、32 人與 revision 183。原本入口只依摘要判定賽事存在，因此會開啟不存在的主文件，且無法再次建立。

已於 2026-11-17 16:01（Asia/Taipei）用原子提交重建空白主文件、同步摘要並新增 `TOURNAMENT_RECREATED` 紀錄。保留「赤式x黑馬記念合作賽」、AKASHIKI 代碼、原公開／封存狀態及既定賽制；選手與賽程為空，回到報名狀態。主文件使用「必須不存在」、摘要使用 updateTime 前置條件，防止覆寫同時建立或更新的資料。原有子集合與其他賽事未修改。

## 程式變更

- 合作賽入口改以 `ensureCloudTournament` transaction 查核主文件，遺失時重建；存在時直接開啟，不覆寫名單。新建與摘要／audit 在同一 transaction，重複或並行進入不會重複建立。
- `clearTournamentContents` 產生保留實際賽制的新 run，runNumber 加一；系列首頁清除也共用此邏輯。
- 單場新制後台加入「清除賽事內容」。顯示影響範圍，輸入賽事代碼確認後清除選手、瑞士輪次、資格設定、入圍名單、淘汰籤表、比分及本輪版本指標，回到報名狀態。
- 使用既有 revision transaction 及 `TOURNAMENT_CLEARED` 稽核；完賽鎖定狀態可合法開始新 run。事件名稱、代碼、規則、公開狀態、共用私人選手檔、audit 與舊 run 版本保留，Firestore Rules 不需放寬。
- 離線、操作中、身分登錄中不開放清除；確認後若資料已更新則拒絕，寫入失敗保留原內容及輸入供重試。
